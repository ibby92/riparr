# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

Riparr is a self-hosted *arr-stack companion. You track **titles** (shows and movies, matched on TMDB) in *arr-style **root folders**; each title has one or more **sources** (container pages: link protectors, paste pages). Riparr polls the sources, finds file-host links, downloads each file once from the preferred host (gofile, pixeldrain, MEGA), extracts archives, and files results under `<root>/<title folder>/[Season NN/]`. See README.md and `docs/` for user-facing behaviour, and `docs/roadmap.md` for what's planned.

## Commands

Node 24 is required (uses built-in `node:sqlite`). On this machine Node comes from nvm and isn't on the default PATH: `export PATH=$HOME/.nvm/versions/node/v24.21.0/bin:$PATH`.

```sh
npm run dev            # next dev + worker (tsx watch) together; data in ./config
npm test               # vitest run (all tests)
npx vitest run lib/mirrors.test.ts          # one file
npx vitest run worker/pipeline.test.ts -t "rate limit"   # one test by name
npm run typecheck      # tsc --noEmit (route types are generated by next dev/build/typegen)
npm run lint
npm run build          # next build (standalone) + esbuild worker bundle -> dist/worker.mjs
npm run release        # lint + typecheck + all tests (7-Zip ones in Docker) + build riparr:<version> and riparr:latest
```

- 7-Zip tests (`worker/extract.test.ts`, the archive case in `worker/pipeline.test.ts`) skip when no `7z` binary is installed. To run everything, use the image's build stage with `p7zip-full p7zip-rar rar` installed (non-free Debian components).
- The runtime image's entrypoint ignores extra `docker run` args; use `--entrypoint node` for one-off commands in it.
- npm blocks package install scripts in this environment, so avoid dependencies that need native builds.

## Architecture

Two processes share one SQLite database (`/config/riparr.db`, WAL):

- **Web** (`app/`, Next.js 16 App Router with `cacheComponents`): UI pages, Server Actions, REST API (`app/api/v1`), and `proxy.ts` (Next 16's renamed middleware) for auth.
- **Worker** (`worker/index.ts`, bundled by esbuild): a 2-second tick loop. Each tick processes commands from the UI, runs due source checks, and runs the download pipeline. It also serves the Click'n'Load listener on :9666.

The UI never calls the worker directly. It writes rows and sends commands through the `commands` table (`lib/commands.ts`: `check_now` (source), `check_title`, `cancel_link`, `cancel_title`, `extract_title`), which the worker claims each tick. Worker liveness is a heartbeat row in `settings`.

### Data model (schema v1, `lib/db/migrations.ts`)

- `root_folders` (absolute paths inside the container, e.g. `/media/Kdrama`) ← `titles` (type show/movie, TMDB fields, `folder`, `season_folders`, `naming`, `monitored`) ← `sources` (container URL, password, poll settings, status).
- `links` belong to a title (unique per `(title_id, fingerprint)`, so two sites listing the same host link share one) and remember the `source_id` that found them. `files` belong to links and carry `season`/`episode`.
- `host_status` / `host_usage`: host-wide cooldowns and per-day bytes (`lib/host-status.ts`). `lib/queue.ts` builds the Queue page's read model.
- Repos: `lib/titles.ts`, `lib/sources.ts`, `lib/root-folders.ts`, `lib/links.ts`.

### Data flow

1. **Poll** (`worker/scheduler.ts` → `worker/check.ts` → `lib/crawlers/index.ts`): fetches each due source page and tries readers in order:
   1. **crate-api:** mkvdrama-style encrypted JSON link list.
   2. **dlc-export:** viewcrate-style `/api/dlc_url/<id>`.
   3. **CNL2:** Click'n'Load data on the page.
   4. **DLC:** the page's `.dlc` link.
   5. **plain:** host links in the HTML.

   New links are diffed in by fingerprint (`lib/links.ts` `addLinks`, normalised via `lib/hosts` `normalizeLinkUrl`), with optional per-link metadata (label, episode, quality, size). If a source throws:
   - `NeedsAttentionError` (captcha, password, page gone (404/410)): the source is marked `needs_attention`.
   - `RateLimitError`: the next check is rescheduled after `Retry-After`.
2. **Resolve** (`worker/pipeline.ts`): each new link's resolver (`lib/hosts/*`, chosen by `findResolver`) lists its files. Files are inserted as `standby`. Hosts without a resolver become link status `ignored`, quietly by design.
3. **Select mirrors** (`lib/mirrors.ts` `planMirrors`, pure), per title across all its sources:
   - Runs only once no link of the title is still `new`/`resolving`.
   - Groups identical files across hosts by name and size, promotes the copy on the best host from `settings.hostPriority`, and keeps the rest on `standby`.
   - Waiting links (rate-limited or backing off) lose priority. Permanently failed or offline links release their files (`failLinkFiles`) so a standby copy takes over.
4. **Download** (`lib/download.ts`): `queued` files are re-resolved for fresh handles, then streamed with Range resume, size and hash checks, stall detection, and an atomic move to `fileDestination()` (`lib/titles.ts`: root + folder + optional `Season NN` + naming template). Partials live at `<root>/.riparr-partial/<fileId>.part`. A host `RateLimitError` of ≥ 2 min puts the whole host in cooldown (`lib/host-status.ts`); its links wait and other hosts' copies are promoted.
5. **Settle**: a link becomes `done` once all its files are done (or covered by mirrors), or `mirror` if every file came from another host. When a title has no pending links, `worker/extract-runner.ts` extracts archives with 7-Zip, serially, recorded in the `extractions` table. It runs only after a title settles, because 7-Zip misreports archives with parts still downloading.

### Key contracts

- `lib/hosts/types.ts`: `HostResolver.resolve()` returns `RemoteFile[]`; `RemoteFile.open(offset)` returns `{body, offset}`, where an offset of 0 means the host ignored Range. Resolvers throw the typed errors from `lib/errors.ts` (`HostOfflineError`, `RateLimitError`, `NeedsAttentionError`). The pipeline's retry and failover logic depends on those error types.
- `lib/crawlers/types.ts`: `CrawlOptions` has two fetches:
  - `fetch`: direct; also used for FlareSolverr and JDownloader's DLC service.
  - `siteFetch`: requests to the container site, possibly proxied.
- `lib/net.ts` `fetchFor("container" | "host")` applies the proxy setting (`RIPARR_PROXY_URL` or Settings; undici `ProxyAgent` / `Socks5ProxyAgent`).

### Database

`lib/db/migrations.ts` is an append-only array (SQL strings, or functions for migrations needing runtime values) tracked by `PRAGMA user_version`. `migrate()` backs the database up to `/config/backups` before upgrading an existing one, and turns foreign keys off around the transaction, because some migrations rebuild tables to change CHECK constraints, which SQLite can't alter. Add a new entry; never edit applied ones. Add an upgrade test in `lib/db/migrations.test.ts` that runs it on data at the previous version. Repositories use the `all`/`one`/`run` helpers in `lib/db/index.ts`, which copy node:sqlite's null-prototype rows into plain objects.

## Conventions and pitfalls

- **Cache Components:** pages read the DB inside `<Suspense>` after `await connection()`. Synchronous SQLite reads would otherwise be prerendered at build time. Route handlers use `api()` in `lib/api.ts`, which does this and re-checks auth.
- **Auth:** every Server Action calls `await requireSession()` (`lib/session.ts`) first. The proxy alone isn't enough, because actions can be POSTed directly. `RIPARR_AUTH=none` disables auth for recovery.
- **Client components must not import modules that reach the DB or Node APIs.** Use client-safe modules such as `lib/host-ids.ts` and `lib/notify-events.ts`, and `import type` for everything else.
- **`megajs` must stay out of the Next build.** `lib/hosts/mega.ts` imports it type-only and loads it with `import(/* turbopackIgnore: true */ "megajs")`. The worker bundle includes it. Making it a static import breaks the standalone Docker server.
- **Secrets never reach the browser.** Host-account secrets and the TMDB key aren't rendered back (an empty input means "keep"). The proxy URL is masked server-side (`maskProxyUrl`). API responses omit source passwords (`sourceDto`). Notifications send only the title's `{id, name}`.
- **UI:** pages live in `app/(app)/` (inside the app shell: `_shell/`) and `app/(auth)/` (login, setup). Build pages from the kit in `app/(app)/_kit/` and the tokens in `app/tokens.css` (Tailwind classes like `bg-surface`, `text-muted`, `bg-warn-soft`); never hex or Tailwind palette colours, so light and dark both work. Design spec: `design/README.md`; reference mockup: `design/mockups/index.html`. Icons: `lucide-react`.
- **Tests:** test files set `RIPARR_CONFIG_DIR` to a temp dir (and add a root folder there) before dynamically importing modules. Time-dependent worker logic uses the injectable `clock` in `lib/host-status.ts`. End-to-end tests (`worker/pipeline.test.ts`) run a local HTTP server, register fake resolvers by pushing onto `RESOLVERS`, and build real CNL2, DLC and crate-api payloads with the fixtures in `lib/crawlers/*-fixture.ts`. No test hits the network.
- **Container sites deliberately deter automation.** Use the interfaces the sites offer (encrypted list API, DLC export, Click'n'Load). Don't impersonate a browser to get past explicit blocks: viewcrate's `/get/` resolver answers "Blocked automated redirect probe", and Riparr uses its DLC export instead.
- **Ports:** the UI is on 7676 (7878 is Radarr's) and Click'n'Load on 9666. The Docker healthcheck hits the unauthenticated `/api/health`.
