# Development

## Setup

You need Node 24 or newer: Riparr uses the built-in `node:sqlite`, which is why there's no native database driver.

```sh
npm install
npm run dev        # next dev (:3000) + worker in watch mode, together
```

Development data goes in `./config` (git-ignored; `RIPARR_CONFIG_DIR` overrides it). Add a root folder under Settings → Media Management, e.g. the absolute path of `./downloads` (git-ignored), before adding titles. To run only one side: `npm run dev:web` or `npm run worker`.

The dev server works from other devices on your network: `next.config.ts` allows this machine's own addresses (Next 16 otherwise blocks its dev resources for anything but `localhost`). To open it under another name, such as a DNS name or reverse proxy, list it in `RIPARR_DEV_ORIGINS` (comma-separated) and restart `npm run dev`.

> **Next.js 16:** APIs and conventions differ from older versions; for example, middleware is now `proxy.ts`, and `cacheComponents` changes how data fetching renders. Read the guides bundled in `node_modules/next/dist/docs/` before writing Next-specific code. `AGENTS.md` says the same.

### Running the 7-Zip tests

The extraction tests skip when no `7z` binary is installed. To run the full suite with nothing skipped, use the image's build stage:

```sh
docker build --target build -t riparr:build-test .
docker run --rm riparr:build-test sh -c "
  sed -i 's/^Components: main$/Components: main non-free/' /etc/apt/sources.list.d/debian.sources &&
  apt-get update -qq && apt-get install -y -qq p7zip-full p7zip-rar rar >/dev/null && npx vitest run"
```

## Project layout

```
app/            Next.js routes: pages, Server Actions (actions.ts), REST API (api/v1)
lib/            Shared by web and worker: data access, crawlers, host resolvers, downloader, auth, settings
  crawlers/     Container page readers (one module per kind of page)
  hosts/        File-host resolvers (gofile, pixeldrain, mega) + shared HTTP helpers
  db/           SQLite connection and migrations
worker/         Worker entry point, scheduler, pipeline, extraction, Click'n'Load server
proxy.ts        Auth gate for every request
docker/         Entrypoint script
```

See [architecture](architecture.md) for how the pieces fit together.

## Conventions

- **Data access:** repositories in `lib/*.ts` call the `all`/`one`/`run` helpers from `lib/db`. node:sqlite returns null-prototype rows; the helpers copy them into plain objects.
- **Migrations:** append to `MIGRATIONS` in `lib/db/migrations.ts` and never edit an applied entry. Bump the expected version in `lib/db.test.ts`. For table rebuilds (needed to change CHECK constraints), add an upgrade test to `lib/db/migrations.test.ts`. `migrate()` already turns foreign keys off around the transaction.
- **Pages:** read data inside a `<Suspense>` child after `await connection()`. With Cache Components, a synchronous SQLite read would otherwise be prerendered at build time. The `react-hooks/purity` lint rule flags `Date.now()` in render; the existing pages disable it once per request-time component, with a comment.
- **Server Actions:**
  - Call `await requireSession()` first.
  - Validate with zod.
  - Return field errors **and the submitted values**, because React 19 resets forms after an action.
  - A `"use server"` file can only export async functions; put schemas in `lib/`.
- **Client components** must not import modules that reach `lib/db` or Node APIs. Keep client-safe constants in their own modules (`lib/host-ids.ts`, `lib/notify-events.ts`) and use `import type` for the rest.
- **Typed errors:** resolvers and crawlers signal outcomes with the errors in `lib/errors.ts`. The pipeline's retry, failover and needs-attention behaviour depends on the error type, so pick the right one.

## Testing

All tests run offline:

- **Database tests** set `RIPARR_CONFIG_DIR` / `RIPARR_DOWNLOADS_DIR` to a temp directory, then load modules with `await import()`, so the database opens there.
- **Crawler and resolver tests** inject a fake `fetch` through the options (`CrawlOptions.fetch` / `siteFetch`, `ResolveOptions.fetch`).
- **End-to-end tests** (`worker/pipeline.test.ts`) start a local HTTP server that acts as both container sites and file hosts, and register fake resolvers by pushing onto `RESOLVERS`.
- **Fixtures** that build genuine encrypted payloads:

  | Fixture | Builds |
  | --- | --- |
  | `lib/crawlers/dlc-fixture.ts` | A real DLC file, plus the `<rc>` value JDownloader's service would return |
  | `lib/crawlers/crate-fixture.ts` | An mkvdrama-style page and its encrypted API response |
  | `cnl2Page()` in the pipeline test | A Click'n'Load page |

- **Proxy tests** (`lib/net.test.ts`) run a real HTTP CONNECT proxy and a minimal SOCKS5 server.

## Adding a file host

1. Create `lib/hosts/<host>.ts` exporting a `HostResolver` (`lib/hosts/types.ts`):
   - `id`, the short name used in settings, e.g. `"filehost"`;
   - `matches(url)`;
   - `resolve(url, opts)`, returning `RemoteFile[]`. Use `httpOpener(url, { fetch: opts.fetch, headers })` from `lib/hosts/http.ts` for downloads; it handles Range resume and maps 404, 410 and 429 responses to typed errors.
   - Pass `opts.fetch` through everywhere, so the proxy scope and tests work.
   - Throw `HostOfflineError`, `RateLimitError(msg, retryAfterMs)` or `NeedsAttentionError` as appropriate.
   - Give each file a `key` that stays the same across re-resolves (the host's file id). Resume and mirror matching depend on it.
2. Add it to `RESOLVERS` in `lib/hosts/index.ts`, and teach `normalizeLinkUrl` its canonical URL form if it has alias domains.
3. Add it to `KNOWN_HOSTS` in `lib/host-ids.ts`; a test checks the two lists match. Add its domains to `lib/crawlers/known-hosts.ts` if plain pages should detect it.
4. If it takes credentials, add its fields to `ACCOUNT_FIELDS` in `lib/host-accounts.ts`.
5. Add tests with a fake `fetch`, like `lib/hosts/pixeldrain.test.ts`.

## Adding a container source

For a new kind of container page:

1. Put the parsing and decryption in a pure module in `lib/crawlers/` (see `crate-api.ts`), so it can be unit-tested from an HTML string.
2. Wire it into `crawlPage()` in `lib/crawlers/index.ts`:
   - Detect the page by its **structure**, not its domain, so other sites running the same software work too.
   - Return `null` when the page isn't yours.
   - Make every request to the site with `siteFetch(opts)`, passing the page's cookies and User-Agent.
   - Return `items` metadata if the site provides it.
3. Map the site's 429 to `RateLimitError`, and human-required states to `NeedsAttentionError`.
4. Add a fixture and an end-to-end polling test.

Container sites deliberately obfuscate their pages and deter automation. Use the interfaces they offer: the data their own page loads, DLC exports and Click'n'Load. Don't impersonate a browser to get past explicit blocks.

## Release checklist

- `npm run lint && npm run typecheck && npm test`
- The full suite with 7-Zip (above)
- `npm run build && docker build -t riparr:<version> .`
- A smoke test: start the image with temporary volumes and check that `/api/health` and the main pages respond
